How a run flows (A2A native mode)

  1. 1The presenter picks a disruption in the Control Tower UI. The local backend streams every agent event back live.
  2. 2The backend calls the Caldova Coordinator through the Foundry Responses API, authenticated with Entra ID.
  3. 3The Coordinator delegates to the Caldova Logistics Analyst over A2A, agent to agent, inside Foundry.
  4. 4The Analyst runs its LangGraph tools: ERP lookups, recovery-option math, and Web Search through the Foundry Toolbox (MCP).
  5. 5The Coordinator checks the Caldova policies with File Search and writes the final recommendation.
  6. 6Spans from the backend, the Foundry service and the hosted container land in Application Insights as a single trace. Foundry also scores the Coordinator's answers with continuous evaluation, shown on its Monitor tab.

Good to know

  • •Agents, models and tools use keyless Entra ID authentication; only telemetry uses the Application Insights connection string.
  • •The app runs locally; only the agents, models and tools run in Azure.
  • •Answer quality is graded by built-in Foundry evaluators, with GPT-5.4-mini as the judge.
  • •All company data is fictitious.
